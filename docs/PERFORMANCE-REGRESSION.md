# 性能诊断与游戏回归

配置默认保持已验证路径。实验时在两份 bridge.conf 设置：

```ini
bridge.performanceDiagnostics = True
bridge.queueSpaceWait = True
```

性能日志为游戏工作目录中的 yr-bridge-performance-进程ID.log，每约5秒按活动采样。记录空队列和满队列事件等待耗时、纹理视图映射耗时、缓存命中次数、纹理上传调用耗时和上传字节数。日志是各进程的累计值；最后不足5秒的活动可能没有落盘。上传统计覆盖 Surface Unlock 上传，未覆盖所有顶点/索引/体积纹理传输。共享堆上传不计复制字节。性能统计会产生额外开销，正式加载速度对比时关闭统计。

满队列优化使用单独的空位事件、等待标志和能力标记。有界自旋后最多等待10ms，重新检查队列及原有超时；旧对端不支持能力标记时回退原路径。默认关闭以便同版本A/B测试。

固定同一地图、阵营、AI数量、分辨率、覆盖层设置，分别测试旧版基线、新版关闭优化、新版开启优化。每套至少3轮；区分首次冷缓存与后续热缓存。

```powershell
./scripts/Measure-GameRegression.ps1 -Label baseline -Map 地图名 -Rounds 3
python scripts/summarize-regression.py regression-results
```

工具逐轮提示地图加载、存档后读档、切换地图，后台每秒采样游戏和Host内存/CPU。到可操作时确认，失败输入fail；耗时包含人工反应时间，不能视为引擎内部精确计时。存读档请使用专门测试存档。至少连续切换10次地图，观察私人内存是否持续增加，并在退出游戏后确认Host退出。

验收：不能出现1/4停顿、超时、闪退或花屏；加载耗时应与基线相当或更好；CPU改善需结合累计CPU与采样时长计算，不能只看单次任务管理器百分比。工作集下降不能单独证明泄漏修复。

云端测试验证队列满时低CPU等待、唤醒、取消、回绕及双向跨位数传输。实际地图、存读档和切换结果仍须运行游戏后产生，未填写结果代表未实测。
